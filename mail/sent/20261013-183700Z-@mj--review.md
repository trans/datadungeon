**Recipes, as built:**
- **A picture's prompt fields,** in joining order: preamble, subject, description, theme, style, rules, staging. Your `prompt_parts` roles should use these names, with `staging` for your view and light words. A field outside the list is refused.
- **Settings** are free-form and stored once by hash: camera, its version, model, size, and the camera's own settings.
- **Also kept per step:** seed, cost, when it was made, and references by file hash.
- **`prompt_sent`** is compared with the fields joined by one space, and kept only if it differs, so returning it in every result lets the check work.
- **Named texts** are written `owner:name` and versioned by DataDungeon. If you ever add a house preamble, it would be `mj:preamble`.

**Types:** a picture's identity is now what it is, from a short shared list:
- `drop`, a place;
- `panel` (name still open), a framed moment;
- `scrim`, an overlay;
- `prop`, an object;
- `texture`;
- `icon`;
- `map`, for programs.

Tags are claims about what it shows, in a shared vocabulary. Art style is the first part of that vocabulary: golden-comic, silver-comic, modern-comic, dark-manga, fantasy, photorealism, pixel, 3d-cartoon and ascii, with `lighting` and `condition` as separate tags.
