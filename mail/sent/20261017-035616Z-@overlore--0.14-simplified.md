**The recipe**

- **`prompt:` is what the provider was sent,** whole, as you built it: a picture's prompt, the words a voice speaks, a chat model's input. **`instructions:`** is speech's and a chat text's second input (a voice's instructions); a picture has none.
- **`wordings:`** lists the named wordings that went in: `Recipe.wording(kind, "owner:name[/purpose]", words)`. The kind is free: `style`, `flavor`, `rating`, `framing`, `character`, `theme`, ….
- **A version is the words' hash,** the first 10 hex characters of their SHA-256, so `dd:silver-comic@12063ea05a` is the same words in every store (@mj's idea). A wording is never changed or deleted; the store refuses both. New words are a new version.
- **The style is the vocabulary's:** a picture's `style` wording is `db.style_text("silver-comic")` ("Silver Age comic.", `dd:silver-comic@12063ea05a`). Your own words for it are a `flavor` named for the same style: `overlore:silver-comic/place`. DataDungeon's own owner is now `dd`, not `datadungeon`.
- **Checked when you store,** before anything is written:
  - each wording's words are in the prompt or instructions, word for word;
  - a version you give matches the words;
  - you add wordings only under your own consumer name, and a `dd:` wording must be DataDungeon's words;
  - a picture's style is `dd:` and its flavor is named for that style.

  `recipe.check` catches the first two before you call the provider. Recipes stored before 0.14 aren't checked.
- **Reading:** `db.recipe(id)` returns the prompt, the instructions and the wordings, named with `@version`. `with_text(kind, name)`, `list_assets(texts:)`, `named_texts(kind, owner)` and `text.<kind>=` work as before, over the wordings. `GET /assets/:id/recipe` returns `{form, settings, prompt, instructions, wordings: [{kind, name, text}], …}`.
- **Gone:** `Recipe::Text`, `Recipe.text`, `Recipe.named`, `fields`, `joined`, `prompt_sent` and `with_prompt_sent`.
- **The order of a prompt's parts is advice now,** in the README with what each part is for, not a schema: rules · framing · style · flavor · theme · subject · description · staging · light · directives. Your code keeps the parts and joins them.
