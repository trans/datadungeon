Thanks, all of that works for curio. The hub deletes files other stores rely on, so most of this is about making a mistake impossible rather than unlikely. Thomas says the hub can wait until the current work is done, so none of this is urgent.

**Clearing the bucket safely:**
1. **The bucket should say it's shared, not each app.** `shared:` is an option an app passes when it opens its store, so one app that leaves it out deletes files other stores use, on its next prune or vacuum. A marker in the bucket, which DataDungeon checks on opening, would make every store that opens it shared. A store on a DataDungeon older than 0.13 can't check the marker, so it must never be pointed at the bucket.
2. **Every store sharing the bucket registers itself there** when it opens: its name, where it's served, and when it was last opened. The hub then clears only when every registered store has answered, instead of trusting its own list of stores. A store that is gone for good is removed from the register by a person, through curio.
3. **`GET /objects`** should be read in one transaction, and paged or streamed, since a store may hold a million files. Including retired assets is right.
4. "Written since the run began" will be judged by the bucket's own clock: the hub writes a marker at the start and reads back its date. Clock differences between machines then can't matter.

**Copying:**
5. **Record a copy without sending the bytes,** over HTTP too. That means a row for a file already in the bucket, given by its hash, carrying:
   - tags, description and recipe
   - image fields
   - the `copied-from` link

   The store checks the file is there and refreshes its date.
6. **Text hashes in a recipe's JSON,** as descriptions now have. A named text's version is counted in each store separately, so `overlore:silver@2` in one store can be `@1` in another. Only the hash says two wordings are the same.

**Searching as one:**
7. **A stable sort with a cursor** (after this rating and id), so the hub can merge several stores' results in order. Page numbers don't merge.
8. **`GET /store`:** its name, DataDungeon version, and whether its storage is shared and with which bucket. The hub can then check a store before relying on its list.
9. Later: a feed of changes since a point (the `asset_changes` table looks like a start). With it the hub could keep its own index instead of asking every store on every search.
